# v1.7 지시서 — 사용자 단축키(여러 개, 기능 고르기)

설계: Opus · 구현: Codex Sol(`gpt-6.1-sol`) · 감사: Codex Astra(`gpt-6-astra`)
사용자 요청 원문(2026-11-16): "설정에 단축키 좀 여러 개(숫자키 외에도) 새로 설정도 할 수 있게 해 줘(디폴트는 없게 하되 원할 때 지정할 수 있게). 키는 지정할 수 있게 해 주고(녹화), 기능은 네가 적절히 쓸 만한 거 몇 개 해 놔. 드롭다운으로 이 시계 외 모든 창 끄기라든지, 다른 창에 있다가 시계로 돌아오기라든지, 볼륨 조절 등등 사용자 편의를 고려한 기능들."

## 결정 요약

- v1.6의 '시계로 돌아오기' 단축키 1개(`returnHotkey`)를 **목록형 사용자 단축키 `customHotkeys`로 일반화**합니다. '시계로 돌아오기'는 그 목록의 기능 중 하나가 됩니다.
- 모든 사용자 단축키는 **전역**입니다(어느 창이 앞에 있든 동작, Electron `globalShortcut`). 숫자패드 단축키(시계가 맨 앞일 때만)는 지금 그대로 둡니다.
- 기본값: 새로 설치하면 `[{ 시계로 돌아오기, Ctrl+H }]` 한 줄만 둡니다(v1.6에서 사용자가 요청한 것). 그 밖의 기능은 기본값이 없고, 사용자가 '단축키 추가'로 만듭니다.

## A. 설정·이관

1. 설정 `customHotkeys: [{ id, action, arg, combo }]`, 최대 **12개**.
   - `id`: `'h' + 숫자`(목록 안에서 유일).
   - `action`: 아래 B 표의 id.
   - `arg`: `slot`일 때만 1~9, 그 밖에는 `null`.
   - `combo`: `keycombo.js` 형식이고 `''`이면 아직 지정 안 함.
2. `store.js` 정규화
   - 알 수 없는 `action`은 항목째 버립니다.
   - `slot`의 `arg`가 범위를 벗어나면 1로 둡니다.
   - `combo`가 `formatCombo`로 바뀌지 않는 깨진 값이면 `''`로 둡니다.
   - 13번째 항목부터는 버립니다.
3. `settingsVersion` 4 이관(한 번만)
   - 옛 `returnHotkey`가 올바른 값이면 → `[{ id:'h1', action:'return', arg:null, combo: 그 값 }]`.
   - 옛 `returnHotkey`가 `''`(사용자가 지움)이면 → `[]`.
   - 그 뒤 `returnHotkey` 키를 지웁니다.
   - 새 설치는 `[{ id:'h1', action:'return', arg:null, combo:'Ctrl+H' }]`로 시작합니다.
   - 이관 시험을 3가지 경우(값 있음·빈 값·새 설치)로 둡니다.

## B. 기능 목록(드롭다운, 이 순서)

| id | 이름(ko) | 동작 |
|---|---|---|
| `return` | 시계로 돌아오기 | v1.6과 같음. 시계가 이미 포커스면 무동작. 아니면 `foreground.cancelWait()` 후 `bringToFront()` |
| `minimizeOthers` | 시계 외 모든 창 최소화 | 아래 '창 고르기' 규칙에 맞는 창마다 `PostMessageW(hwnd, WM_SYSCOMMAND, SC_MINIMIZE, 0)` → `bringToFront()` → 토스트 '창 n개를 내렸습니다' |
| `closeOthers` | 시계 외 모든 창 닫기 | 같은 규칙의 창마다 `PostMessageW(hwnd, WM_CLOSE, 0, 0)`(정상 닫기 요청이라 저장 안 한 문서는 앱이 직접 묻습니다. 프로세스 강제 종료 금지) → `bringToFront()` → 토스트 '창 n개에 닫기를 요청했습니다' |
| `volumeUp` / `volumeDown` | 볼륨 올리기 / 내리기 | 기존 `system.volume(true/false)`(1회 누름당 2칸). 키를 누르고 있으면 반복해서 동작해도 됩니다 |
| `mute` | 음소거 켜기/끄기 | `keybd_event(VK_VOLUME_MUTE 0xAD)` |
| `playPause` / `nextTrack` / `prevTrack` | 재생/일시정지 · 다음 곡 · 이전 곡 | `keybd_event` `VK_MEDIA_PLAY_PAUSE 0xB3` / `VK_MEDIA_NEXT_TRACK 0xB0` / `VK_MEDIA_PREV_TRACK 0xB1`(유튜브 등 브라우저 미디어에 적용) |
| `slot` | 슬롯 n 실행 | 숫자패드 n과 같은 실행 경로. 실행 IPC 처리부를 함수 `runSlot(n, { force })`로 빼서 둘 다 그 함수를 씁니다. `hotkeysOn`이 꺼져 있어도 동작(전역 단축키는 사용자가 따로 지정한 것이므로) |
| `timer` | 타이머 열기 | `bringToFront()` 후 렌더러에 `command` 이벤트 `{ type:'timerOpen' }`를 보냅니다. 렌더러는 키 `T`와 같은 상태 전이를 합니다(설정 서랍이 열려 있으면 무시) |
| `night` | 야간 모드 전환 | 렌더러에 `{ type:'nightToggle' }`를 보냅니다. 키 `N`과 같은 처리(토스트 포함)를 하고, `keys.js`의 같은 전이 함수를 재사용합니다 |
| `fullscreen` | 전체화면 켜기/끄기 | v1.6 `window:toggleFullscreen`과 같은 함수를 씁니다 |
| `screenOff` | 화면 끄기 | `PostMessageW(HWND_BROADCAST 0xFFFF, WM_SYSCOMMAND, SC_MONITORPOWER 0xF170, 2)`. 마우스나 키를 건드리면 Windows가 다시 켭니다. `SendMessage` 금지(멈출 수 있음) |

**창 고르기**(`minimizeOthers`·`closeOthers`): 순수 함수 `pickOtherWindows(list, selfPid)`로 만들어 가짜 목록으로 시험합니다. 입력은 koffi `EnumWindows`로 모은 `{ hwnd, pid, cls, title, visible, owned, toolWindow, cloaked, minimized }`이고, 아래 조건을 **모두** 만족하는 창만 고릅니다.
- 화면에 보이는 창
- 다른 창에 딸린 창이 아님(`GetWindow(GW_OWNER)` 없음)
- 도구 창이 아님(`WS_EX_TOOLWINDOW` 없음)
- 숨겨진 UWP 창이 아님(`DwmGetWindowAttribute(DWMWA_CLOAKED)` 0)
- 제목이 비어 있지 않음
- 시계 자신의 창이 아님(`pid !== selfPid`, Electron 프로세스 전체)
- 바탕화면·작업 표시줄 창이 아님(클래스가 `Progman`·`WorkerW`·`Shell_TrayWnd`·`Shell_SecondaryTrayWnd`·`Windows.UI.Core.CoreWindow` 가 아님)
- `minimizeOthers`에서는 이미 최소화된 창도 제외

koffi 콜백은 `koffi.proto` + `koffi.register`로 만들고, 다 쓰면 `koffi.unregister`로 해제합니다. 구현은 `foreground.js` 또는 `system.js` 중 기존 Win32 선언이 있는 쪽에 둡니다.

## C. 등록 모듈

`hotkey.js`를 목록용으로 넓힙니다: `createHotkeys({ shortcut, onPress(entry) })`.
- `apply(list)`
  - 이전에 등록한 것을 모두 해제합니다(**자기 것만**, `unregisterAll` 금지).
  - 항목마다 상태를 매깁니다. 판정 순서는 아래와 같습니다.
    - `'off'`: 조합이 빈 값
    - `'invalid'`: `toAccelerator`가 `null`
    - `'dup'`: 목록 안에서 앞 항목과 같은 accelerator
    - `'taken'`: `register`가 false를 돌려줌
    - `'ok'`: 등록 성공
  - 결과를 `{ [id]: state }`로 돌려주고 `states()`로도 읽게 합니다.
- `suspend(on)` / `dispose()`: 의미는 v1.6과 같습니다(녹화 중에는 전부 해제).
- `toAccelerator` 허용 범위를 넓힙니다. Ctrl·Alt·Win 중 하나 이상이 있는 조합에 더해, **수정키 없는 F1~F24 단독**도 허용합니다. Shift만 붙은 조합이나 수정키 없는 글자·숫자·Space·Enter·Tab·Esc는 여전히 `null`입니다. 시험을 갱신합니다.
- `onPress(entry)`는 `main.js`에서 B 표에 따라 나눠 보냅니다. 기능 하나가 예외를 던져도 다른 단축키에는 영향이 없어야 합니다(try/catch 후 토스트 '단축키 실행 실패').
- IPC는 `hotkey:state`를 `hotkey:states`로, `hotkey:suspend`는 그대로 둡니다. preload도 맞춥니다. `settings:set`에 `customHotkeys`가 있으면 `apply`합니다.

## D. 설정 서랍 '단축키' 탭

맨 위 v1.6 '시계로 돌아오기' 행 자리에 **'사용자 단축키'** 묶음을 둡니다.

- 행마다 한 줄(서랍 폭 520px 안):
  - [기능 드롭다운]
  - (`slot`일 때만) [1~9 드롭다운]
  - [조합 표시 또는 '지정 안 함']
  - [녹화]
  - [삭제]
- 녹화 UI는 v1.6 `sendKeysRow` 방식을 재사용합니다.
  - 녹화를 시작하면 `hotkeySuspend(true)`, 끝·취소·서랍 닫힘·탭 이동 때는 반드시 `false`로 되돌립니다.
  - 녹화 중 Backspace·Delete는 조합을 비웁니다.
  - 허용되지 않는 조합은 저장하지 않고 안내만 합니다.
- 행 아래에 작은 상태 문구를 둡니다.
  - `taken`: '다른 프로그램이 이미 쓰는 조합입니다'
  - `dup`: '위의 단축키와 같은 조합입니다'
  - `invalid`: 'Ctrl·Alt·Win과 함께 누르거나 F1~F24를 쓰세요'
  - `ok`·`off`: 문구 없음
- `closeOthers` 행에는 늘 작은 경고를 붙입니다: '시계를 뺀 모든 창에 닫기를 요청합니다(저장 안 한 문서는 각 앱이 묻습니다)'.
- 맨 아래 '+ 단축키 추가'를 둡니다. 새 행은 기능 `return`, 조합 `''`로 시작하고, 12개가 되면 비활성으로 바꿉니다.
- 묶음 위에 한 줄 안내를 둡니다: '여기서 정한 단축키는 다른 프로그램을 쓰는 중에도 동작하며, 그 프로그램의 같은 단축키는 시계가 켜져 있는 동안 동작하지 않습니다.'
- 기능 이름과 문구는 모두 3언어(ko·zh·en)로 둡니다.
- 화면 아래 단축키 안내 줄(`buildLegend`)은 바꾸지 않습니다.

## E. 시험

- `store`: 정규화와 이관 3가지 경우.
- `toAccelerator`: F 키 단독 허용, 글자 단독·Shift만 거부.
- `hotkey`(가짜 shortcut):
  - 목록에서 ok·off·invalid·dup·taken 판정
  - 다시 적용할 때 이전 것 전부 해제
  - suspend·재개
  - dispose
- `pickOtherWindows`: 조건마다 걸러지는 경우 하나씩, 그리고 최소화 제외 옵션.
- 기능 나눠 보내기: `main.js` 밖의 순수 함수(예: `hotkeyActions.js`의 `dispatch(entry, deps)`)로 빼서, 가짜 deps로 모든 action이 맞는 deps 함수를 부르는지와 예외 격리를 시험합니다.
- `i18n` 키가 3언어에서 일치하는지.

## 공통 규칙

- 최소 변경으로 고칩니다. 기존 시험은 전부 유지하고(현재 118개) `npm test`가 통과해야 합니다.
- 수정한 파일 끝에 `// 개정 기록 | 2026-11-16 | <요약> | 사용자 요청` 한 줄을 붙입니다.
- **실제 시스템에 영향을 주는 기능은 검증 때 진짜로 실행하지 않습니다.** 창 최소화·닫기, 화면 끄기, 볼륨·음소거·미디어 키 전송이 그렇습니다. 이 PC에는 사용자의 작업 창이 열려 있습니다. 시험은 전부 가짜 주입으로 하고, 실제 앱을 띄울 때도 이 기능들에 조합을 지정하지 않습니다.
- 화면 확인은 `python -m http.server`(백그라운드, 끝나면 종료) + 헤드리스 Edge 스크린샷으로 합니다. Edge는 `--headless`와 새 임시 `--user-data-dir`(ASCII 경로)로만 실행하고, 자기가 띄운 PID만 종료합니다(이름 단위 종료 금지). 스크린샷 경로도 ASCII로 하고 끝나면 삭제합니다. 찍은 PNG를 직접 열어 설정 서랍 '단축키' 탭이 3언어 × 행 0개·3개·12개(`slot`·`closeOthers` 포함)에서 겹치거나 잘리지 않는지 확인합니다. 실제 앱이 필요하면 임시 `--user-data-dir` + 슬롯 9개 비움 + 숫자패드 단축키 끔 + `customHotkeys: []` 설정으로만 띄웁니다.
- 실제 앱에서 키 입력은 하지 않습니다. 사용자의 브라우저와 ChatGPT를 실행하거나 종료하지 않습니다. `%APPDATA%\DeskClock`은 쓰지 않습니다.
- 버전은 1.7.0입니다(`package.json`, `package-lock.json` 최상위·`packages[""]`). `npm run dist`는 끝까지 기다리고, 끝나면 `dist`에는 `DeskClock-1.7.0-portable.exe`만 남깁니다. 중간 산출물(`win-unpacked`, `builder-debug.yml`)을 지우지 못하면 조정자에게 요청합니다.
- `docs/architecture.md` §1 '단축키 범위' 행, §4 끝 문단, §10 단축키 탭을 갱신하고 개정 기록 한 줄을 붙입니다. `docs/HANDOFF.md`의 버전·기능 줄도 갱신합니다.
- 문서와 코드에 이 PC의 로컬 경로나 개인 이메일을 쓰지 않습니다(공개 저장소).
- 커밋은 `main` 브랜치에서만, 단계(A·B·C·D·문서·버전/빌드)마다 합니다. **푸시와 `public-release` 조작은 금지**입니다. 커밋 메시지는 한국어로 쓰고 끝 줄은 `Co-Authored-By: Codex <noreply@openai.com>`입니다.
- 끝나면 `docs/v1.7-report.md`에 결과 보고를 한국어로 쓰고 커밋합니다. 바뀐 것, 시험 수, 화면 확인 내용, 못 한 것, 설계와 다른 점을 적습니다.
