# v1.5 작업 지시 — 창 초점·N 야간·일정 출처·모든 테마 정보 완전 표시

설계: Opus · 구현: Gemini Flash High · 2026-11-15 사용자 요청.
작업 전 반드시 읽을 것: `PRODUCT.md`, `DESIGN.md`, `docs/architecture.md`, `docs/theme-contract.md`, `docs/v1.4-people-brief.md`, 그리고 고칠 코드.

## A. 이미 켜진 프로그램: 초점이 안 가고 새 창만 쌓이는 문제

원인: Windows 포그라운드 잠금. 이미 실행 중인 Brave·ChatGPT 등은 시계(맨 앞 프로세스)가 아니므로 스스로 앞으로 못 나오고, `--app=URL`은 누를 때마다 새 창을 만듭니다.

결정:
1. **실행 직전 포그라운드 허락**: 슬롯 실행 직전에 `user32.AllowSetForegroundWindow(ASFW_ANY = -1)`를 호출합니다(koffi, 기존 user32 바인딩에 추가). 시계가 맨 앞일 때만 효과가 있으므로 실행 직전에 부릅니다.
2. **슬롯별 창 기억·재사용**: 슬롯 실행 후 기존 안정 판정(`shouldSend` 흐름)으로 맨 앞이 된 창의 HWND를 그 슬롯의 창으로 기억합니다(메모리만, 저장 안 함). 다음에 같은 슬롯을 누르면:
   - 기억한 HWND가 `IsWindow`로 살아 있으면 **새로 실행하지 않고** 그 창을 앞으로: `IsIconic`이면 `ShowWindow(SW_RESTORE=9)`, 아니면 `ShowWindow(SW_SHOW=5)` → `AllowSetForegroundWindow(-1)` → `SetForegroundWindow(hwnd)`. 실패하면(반환 0) 기존 `bringToFront`와 같은 요령으로 `AttachThreadInput`(시계 스레드 ↔ 대상 창 스레드) 후 `SetForegroundWindow`·`BringWindowToTop`, 끝나면 반드시 분리.
   - 창이 없으면 지금처럼 실행.
   - '실행 후 보낼 키'가 있는 슬롯이 기존 창을 앞으로 꺼낸 경우에도 같은 안정 판정 후 키를 보냅니다(ChatGPT 음성 토글 유지). '실행 후 시계로 돌아오기'도 동일하게 적용.
3. 실행 후 10초 안에 다른 창이 맨 앞이 되지 않으면(초점 실패) 기억하지 않고, 상태 문장은 띄우지 않습니다(기존 동작 유지).
4. 단위 시험: 슬롯 창 재사용 판정을 순수 함수로(`decideLaunch({ rememberedAlive, isMinimized }) → 'focus-existing'|'launch'` 정도) 시험.

## B. N 키 = 야간모드 즉시 전환

- 시계가 맨 앞일 때 `KeyN`(수정키 없음)을 누르면 **야간 강제**를 켜고, 다시 누르면 끕니다. 키 라우팅(`keys.js`)에서 T와 같은 자리: 설정 서랍이 열려 있거나 타이머 입력·울림 중이면 무시. 숫자패드 단축키 끔과 무관(문자 키).
- 야간 강제가 켜지면 색 모드·야간 감광 설정과 관계없이: 다크 모드 + 밝기를 설정의 최소 밝기로(기존 WMI 경로, 실패 시 막). 끄면 원래 모드와 원래 밝기로 복구.
- 야간 강제는 다음 '야간 끝 시각'(`nightEnd`)이 지나면 자동 해제. 앱 재시작 시 해제 상태로 시작(밝기 복구 경로는 기존 비정상 종료 복구 사용).
- 켜고 끌 때 화면에 2초간 작은 안내: '야간 모드'/'야간 모드 해제'(3언어, 기존 토스트 문법).
- 단축키 안내 줄에 `N 야간`(3언어) 추가.
- 단위 시험: 키 라우팅(N 토글, 서랍·입력·울림 중 무시), 자동 해제 시각 계산.

## C. 일정 출처: 공유(커플) 캘린더 vs 개인

v1.4의 '제목·시각 일치' 판정을 **캘린더 기준**으로 바꿉니다.
1. 사람별 캘린더 선택 목록의 각 캘린더에 **'공유' 체크**를 추가(설정 저장: `people[i].calendar.shared: [calendarId…]`).
2. 출처 판정(일정 하나당):
   - 그 캘린더 id를 2명 이상이 선택했거나, 누구든 '공유'로 체크했으면 → **공유**.
   - 같은 일정(`iCalUID` 일치, 없으면 시작+제목 일치 — v1.4 규칙 유지)이 2명 이상 계정에서 왔으면 → **공유**(초대받은 일정 등).
   - 그 밖 → 그 사람 **이름**.
   - 중복은 하나로 합칩니다(공유 판정된 것 우선).
3. 표시:
   - 캘린더를 켠 사람이 2명 이상이거나 공유 캘린더가 하나라도 있으면 출처 표시를 켭니다.
   - 공유 일정 표시 문구는 설정 `sharedLabel`(기본 사전값 '우리'/'我们'/'Us', 사용자가 바꿈, 최대 6자). 연결 탭 '사람' 영역 위에 입력칸.
   - 테마 모델은 v1.4 계약 그대로 `today[i].who`(문구)에 더해 `today[i].whoKind: 'shared'|'person'|null`을 넘깁니다. 공유는 테마 강조색 계열의 아주 작은 알약(배경 10~14% 농도), 개인은 보조색 글자. 크기는 본문 0.6~0.7배.
   - 이번 주 칸의 첫 일정에도 같은 규칙으로 아주 작게(글자만, 알약 없음).
4. 메모: 메모를 켠 사람이 2명 이상이면 이름 묶음(v1.4 그대로).
5. 단위 시험: 공유 판정 4가지 경로, 중복 합치기, 표시 켜짐 조건, `sharedLabel` 기본값·저장.

## D. 모든 테마에서 정보 완전 표시

사용자 지적: 일정 내용이 안 보이는 테마가 있음(네이비·리시버·스탠바이의 '이번 주'가 점·표시등만). **6개 테마 모두** 아래를 빠짐없이 보여야 합니다.
- 날짜(긴 형식), 날씨(온도·상태·최고/최저·우산/마스크), 오늘 일정(시각·제목·출처), **이번 주 7칸(요일 + 첫 일정 제목 말줄임 + '+n')**, 사람별 메모 묶음, 타이머(나타날 때), 단축키 안내 줄, 상태 점.
- 각 테마의 시안 문법을 지키며 추가합니다:
  - 네이비: 오른쪽 열의 점 줄을 '요일 / 제목' 2줄 7칸 띠로(Pretendard 보조색, 다음 일정 강조색 그대로).
  - 리시버: '오늘' 창 아래 표시등 줄을 표시등 + 요일 + 작은 VFD 글자 제목으로(창 높이 안에서, 넘치면 말줄임).
  - 스탠바이: 요일 알약 7개를 '요일 + 첫 일정 한 줄' 알약으로(칸 높이를 늘리고 오늘 목록과 균형).
  - 나머지(바우하우스·섹터·플립)는 이미 제목이 있으면 출처 표시만 추가.
- 확인 범위: 6 테마 × 3 언어 × 라이트/다크 × 폭 1350/1600, 예시 모델 `couple`(2인)·`morning`(1인)·`evening`(긴 제목·넘침). 겹침·잘림·줄바꿈 없음.

## 공통 규칙
- 최소 변경, 기존 시험 유지(현재 94개 통과), 새 문구는 `i18n.js` 3언어(키 일치 시험 통과).
- 수정한 파일 끝 `// 개정 기록 | 2026-11-15 | <요약> | 사용자 요청` 한 줄.
- 화면 확인은 `python -m http.server`(백그라운드, 끝나면 종료) + 헤드리스 Edge 스크린샷. **스크린샷 경로는 반드시 ASCII**(예: `%TEMP%\clockshots\`), 끝나면 삭제. 찍은 PNG를 직접 열어 보고 고칩니다.
- 실제 앱 실행은 임시 `--user-data-dir` + 슬롯 9개를 모두 비우고 단축키 끈 설정으로만. 실제 앱에서 키 입력 금지(DOM 클릭만). Brave·Chrome·Edge·ChatGPT 실행·종료 금지. `%APPDATA%\DeskClock` 사용 금지. 자기가 띄운 Electron만 종료.
- 버전 1.5.0(`package.json`, `package-lock.json` 최상위·`packages[""]`), `npm test` 통과, `npm run dist` 끝까지 기다림, `dist`에는 1.5.0 exe만.
- `main` 브랜치에서만 커밋(`public-release`·원격 금지). 커밋 메시지는 한국어, 끝 줄 `Co-Authored-By: Gemini 3.8 Flash High <noreply@google.com>`.
- 끝나면 `docs/v1.5-report.md`에 결과 보고(바뀐 것, 시험 수, 화면 확인 내용, 못 한 것, 설계와 다른 점)를 한국어로 쓰고 커밋.
