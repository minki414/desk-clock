# v1.8 지시서 — 설치형 전환과 앱 안 업데이트 버튼

설계: Opus · 구현: Codex Sol(`gpt-6.1-sol`) · 감사: Codex Astra(`gpt-6-astra`)

사용자 요청(2026-11-17): "코드를 수정하고 버전을 바꾸면, 이미 깃허브에서 전 버전을 받아 쓰고 있는 프로그램의 설정에서 업데이트 버튼만 눌러서 수정 사항이 반영되게 할 수 있어?"

사용자 결정:
- 배포를 **설치형으로 전환**합니다(Electron 표준 업데이터).
- 새 버전 확인은 **설정의 버튼으로만** 합니다. 앱이 혼자 인터넷으로 확인하지 않습니다.
- 버전을 낼 때마다 GitHub Releases에도 등록합니다.

## A. 패키징

1. `electron-builder` 대상을 `portable`에서 **`nsis`(x64)** 로 바꿉니다. 1.8.0부터는 portable을 만들지 않습니다.
2. NSIS 옵션:
   - `oneClick: true`, `perMachine: false`: 관리자 권한 없이 사용자 폴더 `%LOCALAPPDATA%\Programs\DeskClock`에 설치합니다.
   - `createDesktopShortcut: true`, `createStartMenuShortcut: true`, `runAfterFinish: true`.
   - `deleteAppDataOnUninstall: false`: 삭제해도 설정은 남깁니다.
   - `artifactName: "DeskClock-Setup-${version}.exe"`: 공백 없이 씁니다. `latest.yml` 경로와 같아야 합니다.
3. `build.publish`는 `[{ "provider": "github", "owner": "minki414", "repo": "desk-clock", "releaseType": "release" }]`입니다.
   - 이 설정은 앱 안의 `app-update.yml`을 만들고, 빌드 때 `latest.yml`과 `.blockmap`을 만들게 하는 용도로만 씁니다.
   - **electron-builder의 자동 게시(`--publish`)는 쓰지 않습니다.** 토큰을 환경 변수에 넣지 않습니다.
   - `npm run dist` 스크립트는 `electron-builder --win nsis --x64 --publish never`입니다.
4. 의존성에 `electron-updater`를 **정확한 버전으로 고정**해 추가합니다. `electron-builder` 26.18.0과 짝이 맞는 버전 중 공개된 지 2주 이상 지난 것을 고르고, 고른 근거를 보고서에 적습니다.
5. 코드 서명은 하지 않습니다.
   - 업데이터는 `latest.yml`의 sha512로 무결성을 확인합니다.
   - `publisherName`은 비워 둡니다. 서명 검증을 켜면 서명 없는 설치 파일이 거부되기 때문입니다.
   - 처음 설치할 때 SmartScreen '추가 정보 → 실행' 안내가 나온다는 것을 설치 안내 문서에 적습니다.

## B. 업데이트 모듈 `src/main/updater.js`

`createUpdater({ autoUpdater, isSupported, onState })`를 만듭니다. `autoUpdater`는 주입받아 시험에서 가짜를 씁니다.

설정:
- `autoDownload = false`, `autoInstallOnAppQuit = false`, `allowPrerelease = false`, `allowDowngrade = false`.
- 로그는 버전·상태만 남깁니다. 경로·토큰은 남기지 않습니다.

`isSupported()`는 `app.isPackaged && !process.env.PORTABLE_EXECUTABLE_FILE`입니다. 설치판에서만 true입니다. false이면 모든 동작이 `{ phase: 'unsupported' }`만 돌려줍니다.

상태 `phase`와 다음으로 갈 수 있는 상태:

| phase | 다음 |
|---|---|
| `idle` | `checking` |
| `checking` | `latest` / `available` / `error` |
| `available` | `downloading` |
| `downloading` | `ready` / `error` |
| `ready` | `installing` |
| `error` | `checking` |
| `latest` | `checking` |

- `available`일 때는 `{ version, notes }`를 함께 둡니다. `notes`는 릴리스 본문을 글자로만 바꾼 것이고, 600자까지만 씁니다.
- `downloading`일 때는 `{ percent }`를 함께 둡니다. 정수이고, 값이 바뀔 때만 보냅니다.
- `error`일 때는 `{ message }`를 함께 둡니다. 화면에 보일 문구는 i18n 키로 고르고, 원문은 넣지 않습니다.

함수:
- `check()`: `checking` 중에 다시 부르면 무시합니다.
- `download()`: `available`일 때만 동작합니다.
- `install()`: `ready`일 때만 동작합니다.

`install()` 직전에 메인이 할 일:
- `dimmer.restoreSync()`로 밝기를 원래대로 돌립니다.
- 전역 단축키를 `dispose()`합니다.
- 그다음 `autoUpdater.quitAndInstall(true, true)`로 조용히 설치하고 다시 실행합니다.

IPC와 preload에 노출할 것:
- `update:state`, `update:check`, `update:download`, `update:install`, 이벤트 `update`.
- preload 이름은 `updateState`, `updateCheck`, `updateDownload`, `updateInstall`, `onUpdate`입니다.

**타이머가 동작·일시정지·울림 중이면 `install`을 거부합니다.** 이때 화면 문구는 '타이머가 끝난 뒤 다시 눌러 주세요'입니다.

## C. 설정 서랍 '정보' 탭

버전 행 아래에 '업데이트' 묶음을 둡니다. 버튼 하나와 상태 한 줄로 구성합니다.

| 상태 | 화면 |
|---|---|
| `idle` | [업데이트 확인] |
| `checking` | '확인 중…' (버튼 비활성) |
| `latest` | '최신 버전입니다' + [다시 확인] |
| `available` | '새 버전 1.8.1이 있습니다' + 바뀐 점 요약(작은 글씨, 최대 4줄 후 말줄임) + [업데이트] |
| `downloading` | '내려받는 중 37%' + 얇은 진행 막대 |
| `ready` | 바로 `install()`을 부릅니다. 버튼을 한 번 누르면 업데이트까지 끝나게 하기 위해서입니다. 타이머 때문에 거부되면 [지금 다시 시작해 업데이트] 버튼과 안내를 남깁니다. |
| `error` | '업데이트를 확인하지 못했습니다(인터넷 연결 확인)' + [다시 시도] |
| `unsupported` | 'portable·개발 실행에서는 앱 안 업데이트를 쓸 수 없습니다' + [깃허브에서 받기]. 이 버튼은 `shell.openExternal`로 고정 주소 `https://github.com/minki414/desk-clock/releases/latest`만 엽니다. |

- 사용자는 '업데이트 확인'과 '업데이트' 두 번만 누르면 됩니다.
- 확인은 버튼으로만 합니다. **앱 시작·주기 확인은 넣지 않습니다.**
- 문구는 모두 3언어(ko·zh·en)로 둡니다.

## D. 자동 실행 경로

`autostart.pickPath`가 고르는 경로:
- portable 환경 변수가 있으면 → 그 경로(지금 그대로).
- 없고 `app.isPackaged`이면 → `process.execPath`(설치 경로는 업데이트 뒤에도 같음).
- 개발 실행이면 → `null`.

등록 이름은 그대로 `'DeskClock'`입니다. 그래야 portable에서 설치형으로 옮길 때 기존 로그인 항목이 **덮어써지고 중복되지 않습니다.** 시험으로 확인합니다.

## E. 기존 portable 사용자 이관 안내

이 부분은 코드가 아니라 문서와 릴리스 노트입니다.
- 1.8.0 릴리스 노트와 `docs/setup.md`에 적을 내용:
  - 이번부터 설치형입니다. `DeskClock-Setup-1.8.0.exe`를 실행하면 끝납니다.
  - 설정·구글 연결은 그대로 이어집니다(같은 `%APPDATA%\DeskClock`).
  - 예전 portable exe는 지워도 됩니다.
  - Windows 시작 시 자동 실행을 켜 두었다면 새 앱이 처음 켜질 때 자동으로 새 경로로 바뀝니다.
- 앱 안에서도 안내합니다. portable로 실행 중이면(`PORTABLE_EXECUTABLE_FILE` 있음) '정보' 탭의 `unsupported` 문구 아래에 한 줄을 덧붙입니다: '1.8.0부터는 설치판을 쓰면 여기서 바로 업데이트할 수 있습니다'.

## F. 릴리스 절차(문서화, 이번에는 실행하지 않음)

`docs/HANDOFF.md`와 `docs/architecture.md` §12에 절차를 적습니다.
1. `npm run dist`를 실행하면 `dist`에 `DeskClock-Setup-X.exe`, `.blockmap`, `latest.yml`이 생깁니다.
2. `public-release`에 한 커밋으로 묶어 푸시합니다.
3. `gh release create vX <세 파일> --target <공개 커밋> --title "DeskClock X" --notes-file …`을 실행합니다. Latest로 둡니다.
4. 올라간 `latest.yml`의 `version`, `path`, `sha512`가 로컬 파일과 같은지 확인합니다.

이번 1.8.0의 실제 게시는 감사가 끝난 뒤 조정자가 따로 지시합니다.

## G. 시험

- `updater`(가짜 autoUpdater):
  - 상태 전이 표대로 움직이는가.
  - 중복 `check`는 무시되는가.
  - 잘못된 상태에서 `download`·`install`을 부르면 무시되는가.
  - `unsupported`일 때는 아무것도 하지 않는가.
  - `percent`는 바뀔 때만 보내는가.
  - `notes`는 600자에서 잘리고 HTML이 지워지는가.
  - 오류 원문이 화면 문구로 새지 않는가.
- 타이머 동작 중 `install`이 거부되는가.
- `autostart.pickPath`: portable·설치판·개발 실행 세 경우, 그리고 등록 이름이 늘 같은가.
- 빌드 산출물 확인 스크립트 또는 시험: `npm run dist` 뒤에 아래를 확인합니다.
  - `latest.yml`의 `path`가 `DeskClock-Setup-1.8.0.exe`이고 `sha512`가 실제 파일과 같은가.
  - 설치 파일 안 `resources/app-update.yml`이 GitHub 정보를 가리키는가.
- i18n 3언어 키가 일치하는가.

## 공통 규칙

- 최소 변경으로 합니다. 기존 시험 136개는 유지하고 `npm test`가 통과해야 합니다.
- 수정한 파일 끝에 `// 개정 기록 | 2026-11-17 | <요약> | 사용자 요청` 한 줄을 붙입니다.
- **이 PC에 설치 파일을 실행하지 않습니다.** 설치하면 사용자의 실제 `%APPDATA%\DeskClock`을 쓰게 되기 때문입니다.
  - 실제 업데이트를 처음부터 끝까지 확인하는 일은 사용자 기기에서 1.8.0 → 다음 버전 때 합니다.
  - 그 대신 설치 파일의 내용(asar, `app-update.yml`)과 `latest.yml`은 정적으로 검증합니다.
  - 그리고 `updater.js`는 가짜 시험으로 확인합니다.
- 화면 확인은 기존 방식대로 합니다.
  - `python -m http.server`와 헤드리스 Edge를 씁니다. Edge는 임시 프로필로 띄우고, 자기가 띄운 PID만 종료합니다. 경로는 ASCII로 씁니다.
  - '정보' 탭이 3언어 × 상태 8가지에서 겹치거나 잘리지 않는지 PNG를 직접 열어 확인합니다.
  - 상태는 설정창에 가짜 상태를 넣어서 만듭니다.
- 실제 앱에서 키를 입력하지 않습니다. 사용자의 브라우저를 실행하거나 종료하지 않습니다. `%APPDATA%\DeskClock`은 쓰지 않습니다.
- 문서와 코드에 로컬 경로나 개인 이메일을 쓰지 않습니다.
- 버전은 1.8.0입니다(`package.json`, `package-lock.json` 최상위와 `packages[""]`).
  - `npm run dist`는 끝까지 기다립니다.
  - 끝나면 `dist`에는 Setup exe, `.blockmap`, `latest.yml` 세 파일만 남깁니다.
  - 중간 산출물을 지우지 못하면 조정자에게 요청합니다.
- 커밋은 `main`에서만, 단계마다 합니다. **푸시, `public-release` 조작, `gh release` 실행은 금지**입니다.
  - 커밋 메시지는 한국어로 쓰고, 끝 줄은 `Co-Authored-By: Codex <noreply@openai.com>`입니다.
- 끝나면 `docs/v1.8-report.md`에 결과 보고를 한국어로 쓰고 커밋합니다. 담을 내용은 바뀐 것, 시험 수, 화면 확인, 고른 electron-updater 버전과 근거, 못 한 것, 설계와 다른 점입니다.
