# 감사 지시서 — 키 처리·타이머·토큰 보관 (최소 범위)

토큰 예산이 작습니다. 아래 파일만 읽고, 다른 파일은 꼭 필요한 import 확인 외에는 열지 마십시오. 코드는 수정하지 말고 판정만 하십시오.

기준 문서: `docs/architecture.md`의 §4(키 라우팅), §5(타이머 규칙), §1 표의 '토큰 보관' 행.

대상:
1. `src/renderer/timer-parse.js` — §5 규칙과 정확히 일치하는가(1.3=63초, 1.35=95초, 1.6=66초 유효, 1.60~1.99 무효, 소수 셋째 자리 무효, 0·빈값 무효, 분 4자리 이상 무효).
2. `src/renderer/keys.js` — §4 우선순위·상태 전이가 맞는가. 특히: 타이머 입력 중 숫자패드 1~9가 실행으로 새지 않는지, 단축키 끔일 때 1~9 실행이 막히는지, 반복 키·1.5초 중복 무시, 무효 Enter가 입력 상태를 유지하는지.
3. `src/main/timer.js` + `src/main/main.js`의 타이머·전역 단축키(num0/numadd/numsub) 부분 — 렌더러가 가려져도 메인에서 정확히 울리는지, 단축키 끔·설정 열림에서 전역 키가 해제되는지, num0이 대시보드 포커스일 때 렌더러로 전달되는지.
4. `src/main/google.js` — refresh token이 평문으로 디스크·로그에 남는 경로가 없는지, safeStorage 불가 시 평문 대체 저장이 없는지, PKCE·state 검증, 루프백 서버가 127.0.0.1에만 열리고 끝나면 닫히는지.

출력 형식(한국어, 짧게): 항목별 `PASS` 또는 `FAIL`. FAIL이면 파일:줄, 재현 입력, 기대 동작을 한 줄씩. 사소한 스타일 지적은 쓰지 마십시오. 마지막 줄에 `종합: PASS|FAIL`.
