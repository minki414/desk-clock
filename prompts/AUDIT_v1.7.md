# 감사 지시서 — v1.7 사용자 단축키

코드는 수정하지 말고 판정만 하십시오. 기준 문서는 `docs/v1.7-brief.md`와 `docs/architecture.md`입니다. 범위는 v1.7 지시서 커밋 이후 main의 diff 전체와, 그 diff가 닿는 함수입니다.

**실제 창 최소화·닫기, 화면 끄기, 볼륨·음소거·미디어 키 전송을 이 PC에서 실행하지 마십시오.** 확인은 가짜를 주입해서 합니다.

확인 항목:

1. **설정·이관** (`store.js`)
   - 정규화가 지시서 A-2대로 되는가: 알 수 없는 action은 항목째 버림, slot arg 범위, 깨진 combo는 `''`, 12개 상한.
   - `settingsVersion` 4 이관이 세 경우(값 있음·빈 값·새 설치)에서 맞는가.
   - 이관이 한 번만 일어나는가.
   - 옛 `returnHotkey`가 남거나 다시 생기지 않는가.

2. **등록** (`hotkey.js`, `keycombo.toAccelerator`)
   - 수정키 없는 글자·숫자·Space·Enter·Tab·Esc 조합이나 Shift만 붙은 조합이 절대 등록되지 않는가.
   - F1~F24 단독은 허용되는가.
   - dup 판정이 accelerator 기준인가. 표기만 다른 같은 조합도 같다고 보는가.
   - 다시 적용할 때, 그리고 dispose 때 자기 것만 해제하는가(`unregisterAll` 없음).
   - 녹화 중 suspend 뒤에, 녹화 끝·취소·서랍 닫힘·탭 이동·행 삭제 등 모든 경로에서 다시 등록되는가.
   - 등록 상태가 UI 상태와 어긋나는 경로가 없는가.

3. **기능** (`hotkeyActions` 등)
   - 모든 action이 지시서 B 표대로 나뉘어 처리되는가.
   - 한 기능의 예외가 다른 단축키나 앱 전체에 퍼지지 않는가.
   - `slot`이 숫자패드 경로와 같은 함수를 쓰는가. 같은 슬롯을 1.5초 안에 다시 실행하면 무시하는 규칙과 실패 토스트를 유지하는가.
   - `timer`·`night`가 설정 서랍이 열려 있을 때 무시되는가.
   - `screenOff`가 `PostMessage`를 쓰는가.

4. **창 고르기** (`pickOtherWindows`, `EnumWindows` 배선)
   - 시계 자신, 바탕화면·작업 표시줄, 도구 창, 다른 창에 딸린 창, 숨겨진 UWP 창, 제목 없는 창이 빠지는가.
   - 닫기 기능이 프로세스를 강제 종료하지 않고 `WM_CLOSE`만 보내는가.
   - koffi 콜백을 해제하는가. 콜백이 메모리에서 정리돼 버린 뒤 호출될 위험은 없는가.

5. **회귀와 위생**
   - `npm test` 결과(시험 수).
   - 3언어 문구 키가 일치하는가.
   - v1.6 동작(돌아오기, 전체화면 버튼, 구글 재로그인)이 깨지지 않았는가.
   - 추적 파일에 로컬 경로나 개인 이메일이 없는가(`git grep`).
