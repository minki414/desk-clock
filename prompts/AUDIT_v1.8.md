# 감사 지시서 — v1.8 설치형 전환·앱 안 업데이트

**감사만 합니다.** 코드는 수정하지 말고 판정만 하십시오. 설치 파일도 이 PC에서 실행하지 마십시오.

기준 문서는 `docs/v1.8-brief.md`입니다. 범위는 v1.8 지시서 커밋 이후 main의 diff 전체와 `dist` 산출물입니다.

## 확인 항목

1. **업데이트 안전성**
   - 무결성: 업데이트 파일의 무결성을 `latest.yml`의 sha512로 확인하는가.
   - 업데이트 출처: 출처가 GitHub `minki414/desk-clock` Releases로 고정돼 있는가.
   - 고정 버전: `electron-updater`가 정확한 버전으로 고정돼 있고, `package-lock.json`과 일치하는가.
   - 업데이터 설정: `allowPrerelease`·`allowDowngrade`가 false이고 `autoDownload`·`autoInstallOnAppQuit`도 false인가.
   - 확인 시점: 앱 시작이나 주기적으로 업데이트를 확인하는 코드가 정말 없는가(버튼으로만).
   - 정보 유출: 토큰, 로컬 경로, 오류 원문이 화면·로그·IPC로 새는 경로가 없는가.
   - 고정 주소: `openExternal`이 고정 주소만 여는가.

2. **상태 기계**
   - 전이: 지시서 B의 전이 표와 일치하는가.
   - 거부 동작: 중복 호출이나 잘못된 상태에서의 호출이 무시되는가.
   - 타이머 중 설치: 타이머가 동작·일시정지·울림 중이면 `install`이 거부되는가.
   - 설치 전 정리: 설치 직전에 밝기를 복구하고 전역 단축키를 해제하는가.
   - 지원하지 않는 실행: portable·개발 실행이 `unsupported`로 막히는가.

3. **패키징과 자동 실행**
   - NSIS 설정: 설정 값이 지시서 A와 같은가. 특히 사용자 폴더 설치와, 삭제해도 설정을 남기는 것을 확인하십시오.
   - 설치 파일 이름: `artifactName`과 `latest.yml`의 `path`가 일치하는가.
   - 산출물 검증: 설치 파일 안의 `app-update.yml`과 asar 내용이 main 소스와 일치하는가. 정적으로 확인하십시오.
   - 자동 실행 경로: `autostart.pickPath`가 세 경우(portable·설치판·개발 실행) 모두 맞는가.
   - 로그인 항목 이름: 등록 이름이 `'DeskClock'` 하나라서 portable에서 설치형으로 옮길 때 중복 항목이 생기지 않는가.

4. **화면과 문구**
   - '정보' 탭의 8가지 상태 문구가 3언어로 있는가.
   - 3언어 키가 일치하는가.
   - '업데이트' 버튼을 한 번 누르면 내려받기 → 준비 완료 → 설치가 이어지는가.
   - 설치가 거부됐을 때 다시 시도할 버튼이 남는가.

5. **회귀와 위생**
   - `npm test` 결과의 시험 수.
   - 1.6·1.7 기능이 회귀 없이 동작하는가(가짜 시험).
   - 추적 파일에 로컬 경로나 개인 이메일이 없는가.
